# PlayerKits2 — перенос с PlayerKits v1

Готовый `plugins/PlayerKits2/` с полным переносом содержимого из `PlayerKits` v1:
**12 наборов, 308 предметов, 1:1 по составу, кулдаунам и правам
(+ новый пустой набор `custom` под самый высокий донат).**

## Что нового (v2-фичи, которых не было в v1)

1. **Меню в стиле elytrix.** Верхний блок — серые стёкла, нижний — фиолетовые,
   углы `10, 16, 37, 43` пустые (вырезы), `49` — подсказка (`paper`).
   Отдельной кнопки «Закрыть» нет: меню закрывается `E`.
2. **Четыре состояния иконки набора** вместо одной:
   `display.default` (можно получить) · `display.cooldown` (перезарядка, `%time%`) ·
   `display.no_permission` (нет доступа) · `display.one_time` (уже получен).
3. **Просмотр набора по ПКМ** — та же сетка, что в v1 (`preview_slot` сохранён),
   низ `45–53` закрыт фиолетовым стеклом для красоты,
   `49` — `black_dye` «Назад» со звуком.
4. **Красивое получение:** `title` с названием набора, свой звук у каждого кита,
   фейерверк у `dragon`, `eternity`, `plus`, `custom`.
5. **Тихая ошибка:** если набор на кулдауне / нет прав / нет места — короткий
   `actionbar` и низкий звук вместо «голого» сообщения в чат.
6. **`first_join_kit: start`** — стартовый набор на первом входе (в v1 это был `first_join: true`).
7. **`buy_requirements_inventory`** — готовое меню покупки набора под будущие цены
   (`requirements.price`). В v1 цен не было, поэтому сейчас меню не открывается.
8. **Русские `messages.yml`** с префиксом `&f☁ …ᴇʟʏᴛʀɪx &7» `.
9. **Новый набор `custom`** — самый высокий донат, градиентное имя
   `ᴄᴜѕᴛᴏᴍ` (`#AFFBBE → #E8FFF0`), иконка `NETHER_STAR`, кулдаун 3 дня,
   право `playerkits.kit.custom`. Содержимое пустое — наполняется
   через `/kit edit custom`; при выдаче играет
   `BLOCK_END_PORTAL_SPAWN` + фейерверк.

## Технические замены при переносе

В 1.21 у Bukkit другие имена, поэтому при генерации они переведены:

| v1 | v2 |
|---|---|
| `DAMAGE_ALL` | `SHARPNESS` |
| `DURABILITY` | `UNBREAKING` |
| `PROTECTION_ENVIRONMENTAL` | `PROTECTION` |
| `PROTECTION_FIRE` / `PROTECTION_FALL` / `PROTECTION_EXPLOSIONS` | `FIRE_PROTECTION` / `FEATHER_FALLING` / `BLAST_PROTECTION` |
| `DIG_SPEED` / `ARROW_DAMAGE` / `ARROW_FIRE` | `EFFICIENCY` / `POWER` / `FLAME` |
| `OXYGEN` | `RESPIRATION` |
| `LOOT_BONUS_BLOCKS` / `LOOT_BONUS_MOBS` | `FORTUNE` / `LOOTING` |
| `potion-type: SPEED` + `extended/upgraded` | `LONG_SWIFTNESS` / `STRONG_SWIFTNESS` |
| `FAST_DIGGING` / `INCREASE_DAMAGE` / `CONFUSION` | `HASTE` / `STRENGTH` / `NAUSEA` |
| `hide-flags: HIDE_POTION_EFFECTS` | `item_flags: HIDE_ADDITIONAL_TOOLTIP` |
| `attributes: {GENERIC_MAX_HEALTH: …}` | `attributes: ['MAX_HEALTH;ADD_NUMBER;4.0;elytrix:max_health;offhand']` |
| `banner-color: LIGHT_GRAY_BANNER` + `BlockEntityTag` | `banner_data: {base_color: LIGHT_GRAY}` |
| `book-enchants` | `book_enchants` |
| `permission` | `permission_required: true` (право `playerkits.kit.<набор>` по умолчанию) |
| `slot` | слот в `inventory.yml` (`type: 'kit: <набор>'`) |
| `first_join` | `config.yml → first_join_kit: start` |
| `Commands: ['kit <набор>']` | убрано — это был рекурсивный вызов выдачи из консоли |

## Что перенести нельзя (и что с этим делать)

**1. NBT-теги предметов (`nbt: …`).** С 1.20.5 NBT предмета заменён на data components,
PlayerKits2 пишет `nbt` только на версиях ≤ 1.20.4. Поэтому у 40 предметов отброшены:

* `PublicBukkitValues;{"executableitems:ei-id":…}` — метки **ExecutableItems**;
* `customitems-uuid;…` — метки старого **CustomItems**;
* `Unbreakable;true;boolean`.

Если эти предметы должны быть исполнимыми (например `totem2`, `potion_voina`,
`shalker1…6`, `arrow3`, `elytra1`), их нужно пересоздать в ExecutableItems и выдать
через `actions.claim → console_command`, либо оставить обычными предметами (сейчас
они обычные, но с готовым названием/лором).

**2. `Unbreakable` у элитры в наборе `plus` (предмет 24).** В PlayerKits2 поля
`unbreakable` нет. Варианты:

* оставить как есть — элитра сломается после ~7 минут полёта;
* добавить в `kits/plus.yml → items.24` строку `enchants: ['UNBREAKING;10']`
  (не «вечная», но живёт в 10 раз дольше);
* выдать вручную: `/give <ник> minecraft:elytra[minecraft:unbreakable={}] 1`.

**3. Данные игроков** (`players.yml` v1) файлами не переносятся — для них есть
команда миграции самого плагина (см. ниже).

## Установка (порядок важен)

1. **Не удаляйте** старую папку `plugins/PlayerKits` — из неё читается миграция
   (нужны `kits.yml` и `players.yml`).
2. Поставьте `PlayerKits2.jar` в `plugins/` и запустите сервер.
3. В консоли сервера выполните:

   ```
   kit migrate
   ```

   Плагин перенесёт наборы **и** кулдауны/one-time игроков из
   `plugins/PlayerKits/players.yml` в `plugins/PlayerKits2/players/`.

4. Остановите сервер. Скопируйте файлы этого набора в `plugins/PlayerKits2/`
   с заменой: `config.yml`, `inventory.yml`, `messages.yml`, папку `kits/`.
   В `kits/` должны остаться только 12 файлов — демо-наборы плагина
   (`diamond.yml`, `food.yml`, `iron.yml`) удалите.
   Папку `players/` **не трогайте** — там уже данные игроков.
5. Запустите сервер и проверьте (в игре, под оп-аккаунтом):

   ```
   /kit verify
   /kit open main_inventory <ник>
   ```

   `kit verify` — команда только для игрока, из консоли она не работает.

> Если сначала скопировать файлы, а потом сделать `kit migrate`, плагин
> перезапишет `kits/*.yml` своими (с потерями из раздела выше). Порядок из
> пунктов 3 → 4 обязателен.

## Как править потом

* **Предметы набора** — `kits/<набор>.yml`, ключи `items.<номер>`:
  `id`, `amount`, `name`, `lore`, `enchants` (`'SHARPNESS;5'`), `item_flags`,
  `attributes`, `potion_data`, `skull_data`, `banner_data`, `book_enchants`,
  `offhand`, `preview_slot` (слот в превью, 0–44).
* **Состояния иконки** — `display.default` / `display.cooldown` /
  `display.no_permission` / `display.one_time`.
* **Кулдаун, право, авто-броня** — `cooldown` (сек), `permission_required`,
  `auto_armor`, `one_time`.
* **Меню** — `inventory.yml`: ключ слота может быть числом, списком через `;`
  или диапазоном `9-17`. Набор ставится как `type: 'kit: <набор>'`.
* **Сообщения** — `messages.yml`, префикс и все тексты (ключи менять нельзя).
* **Проверка после правок** — `/kit reload` и `/kit verify`.

Файлы читаются как есть: `/kit reload` их не перезаписывает. Перезапись
происходит только когда набор меняют из игры (`/kit create`, `/kit edit`) —
тогда плагин сохранит файл в своём формате и комментарии в нём не сохранятся.
