# ElytrixDuelsBridge

Мост между **EpicDuels** и **BMenu**: окна плагина подменяются нашими меню
BMenu — с анимацией сборки, звуками и русским текстом.

- Версия: 1.7.1
- Зависимости: `EpicDuels`, `BMenu` (BMenu сам требует `BLib` и `PlaceholderAPI`)
- Paper 1.21.1–1.21.11, Java 17+ (собрано под 17, сервер 21 подходит)
- Java-классы EpicDuels не меняются: мост работает через события и рефлексию
  (единственное исключение — `EpicDuels-ElyTriX-3.1.1.jar`: в нём у арены
  появился общий мир, см. «Арены в одном мире»)

## Что нового в 1.7.1

- шесть (и сколько угодно) арен в одном уже построенном мире `duel` —
  `/duelx arena create|spawn1|spawn2|ready|list|tp|remove`, миры
  `arena_template_*` больше не нужны;
- «Выйти» из поиска работает всегда: мост находит игрока и в своей очереди,
  и в старой очереди EpicDuels, и честно снимает его оттуда;
- киты больше не теряются по русскому имени («Кит не найден: Сумо») —
  имя переводится в id через `Kits.canonical`/`legacyOf`;
- `/duel` во время поиска открывает окно «Ищем бой» с кнопкой отмены;
- `scoreboard.yml` под дуэли: время, противник, кит, карта, раунд, счёт.

## Как работает

1. EpicDuels собирается открыть своё окно (`InventoryOpenEvent`).
2. Мост видит, что владелец инвентаря — `dev.epicduels.gui.MenuHolder`,
   и по типу меню (`MAIN`, `STATS`, `MATCHMAKING`, …) берёт id меню BMenu
   из своего `config.yml`.
3. Окно плагина отменяется, через тик выполняется
   `/bmenu open <меню> <игрок>` — открывается наше меню с анимацией.
4. Кнопки в меню вызывают команды. Где нужен поток плагина — `/duelx`:

```
/duelx pick                      своё окно выбора игрока
/duelx queue <кит|leave>         встать в очередь / выйти
/duelx top                       таблица лидеров
/duelx rounds <1|3|5>            раунды → вызов уходит сразу, карта случайная
/duelx target <ник>              соперник выбран → меню кита
/duelx team                      выбор напарника (быстрый 2 на 2)
/duelx kit <кит>                 кит из нашего меню → раунды или подтверждение
/duelx confirm | cancel          начать бой / встать в очередь / отмена
/duelx kits [reset]              создать 10 готовых наборов (reset — пересоздать)
/duelx open <menu>               открыть меню BMenu
```

Кнопки в чате (`[Принять]`, `[Отклонить]`, `[Выйти]`, `[Встать в очередь]`)
отправляют **`/duel ...`**, а не `/duelx ...`: `/duel` виден клиенту, поэтому
ванильного «вы пытаетесь выполнить нераспознанную команду» не появляется.
`/duelx` остаётся для меню BMenu и админов.

`/duelx` вызывает публичные методы `GUIManager` и менеджеров EpicDuels — то
же, что делает клик в окне плагина. Выбор карты убран: после раундов
`finishChallengeWithArena` получает случайную готовую арену.

## Только две команды для игрока

Игроку не нужно знать подкоманд: `/duel` открывает меню, `/duel ник` — сразу
выбор кита. Мост подменяет обработчик `/duel` у EpicDuels:

- ник в таб-дополнении после `/duel ` (`/duel <Tab>` — список онлайн-игроков);
- подкоманды вроде `arena`, `kit`, `queue`, `stats` игроку недоступны;
- разрешены только те, на которые EpicDuels ставит кнопки в чате:
  `accept`, `deny`, `cancel`, `forfeit`, `rematch`, `toggle`;
- админы (`epicduels.admin` или `elytrix.guard.bypass`) видят полный `/duel`.

Кнопки меню работают через `/duelx`, поэтому фильтр им не мешает.

## Своё окно выбора игрока

Список игроков рисует мост: головы онлайн-игроков, страницы по 45,
без рамки из стёкол — только головы и кнопки. Занятые подписаны «в бою».
Клик сразу открывает выбор кита.
`/duel ник` (и `/d ник`) — быстрый вызов без меню.

Для 2 на 2 в том же окне внизу есть две кнопки: «Случайный тиммейт»
(приглашение случайному игроку) и «Рандом без тиммейта» (очередь 2 на 2
без напарника).

## 10 готовых наборов

Мост сам создаёт киты в EpicDuels (`plugins/EpicDuels/kits.yml`), если их там
ещё нет: `Классика`, `УХК`, `Гаппли`, `Сумо`, `Лучник`, `Булава`, `Топор`,
`Тризуб`, `Арбалет`, `Незерит`. Имена русские, потому что EpicDuels
показывает имя кита как есть — в меню, в сообщениях и на скорборде.

Старые английские id (`sword`, `uhc`, …) при первом запуске переносятся
под русские имена вместе с содержимым, а как команда (`duelx kit sword`)
принимаются как синонимы. Существующие русские киты не перезаписываются,
принудительно — `/duelx kits reset`. Состав описан в `EpicDuels/КИТЫ.md`.

Наборы подобраны так, чтобы работать без установки блоков: кристаллов и
«обсидиановых» китов нет, потому что на аренах блоки ставить нельзя.

Состав усилен (1.6.0): у всех китов есть пёрлы (2–8), больше золотых яблок,
зачарования выше. `Незерит` — тотем в левой руке и тотем в инвентаре,
`Булава` — Density IV и 16 ветряных зарядов, `Арбалет` — Quick Charge III,
`Сумо` — 2 пёрла и перки скорости. Чтобы усиленные наборы появились на
сервере, где киты уже созданы, выполни `/duelx kits reset` (старые вещи
перезапишутся).

## Видимость команд (замена PLHide)

Раздел `command-guard` в `config.yml`:

```yaml
command-guard:
  enabled: true
  duel-menu: true              # /duel: игрокам только «/duel» и «/duel ник»
  hide-tab: true               # не отправлять скрытые команды клиенту
  admin-permission: epicduels.admin
  bypass-permission: elytrix.guard.bypass
  blocked: [plugins, pl, version, ver, about, icanhasbukkit, help]
  hidden:  [plugins, pl, version, ver, about, icanhasbukkit, help,
            bmenu, epicduels, duelx, dx, party, p]
```

- `hidden` — команды исчезают из автодополнения (`PlayerCommandSendEvent`);
- `blocked` — команду нельзя выполнить, в том числе `/bukkit:plugins`;
- OP и права выше видят всё;
- списки можно расширять: `/reload` не нужен, достаточно перезапуска.

Готовые альтернативы, если нужен отдельный плагин:
`CommandWhitelist` (YouHaveTrouble, обновляется в 2026),
`AdvancedPlHide`, `CommandDefender`.

## Выход с арены, пёрлы и высота

Во время боя игрока не выпускает за пределы его арены:

- шаг/полёт за границу отменяется (позиция возвращается);
- пёрл, который улетел за границу или выше лимита, **не телепортирует** —
  просто тратится;
- телепорт в другой мир отменяется (чужой `/spawn`, `/home` тоже);
- команды из `protection.blocked-commands` во время боя не работают;
- если игрок всё же оказался вне зоны, раз в секунду его возвращает на спавн.

Границы считаются по точкам спавна арены:

```
центр  = середина между spawn1 и spawn2
радиус = половина расстояния между ними + protection.arena-margin (20)
высота = max(y spawn1, y spawn2) + protection.max-height (7)
низ    = та же точка − protection.min-drop (25)
```

Поэтому в одном шаблоне можно ставить несколько арен: у каждой свои
spawn1/spawn2, значит и своя зона (главное — не перекрывать зоны соседних
арен, регулируется `arena-margin`). Посмотреть текущие границы в бою:

```
/duelx bounds
```

```yaml
protection:
  leave: true            # границы, телепорт, команды
  pearl-limit: true      # пёрлы за границу / выше лимита
  max-height: 7          # блоков над спавном
  arena-margin: 20       # запас зоны вокруг спавнов
  min-drop: 25           # ниже спавна — возвращаем на спавн
  blocked-commands: [spawn, hub, lobby, tpa, tpahere, tpaccept, warp, home, back]
```

Выход из игры = поражение (это делает сам EpicDuels), сдаться можно
`/duel forfeit`.

## Таймер 3 минуты

Лимит уже в EpicDuels: `duel.time-limit-seconds: 300` в
`plugins/EpicDuels/config.yml`. Отсчёт показывается в action bar
(«Осталось: 2:45»), по нулю:

- 1 на 1 — ничья, если по раундам счёт равный; в bo3 побеждает тот, кто
  ведёт по раундам;
- 2 на 2 — ничья;
- ничья не пишет статистику и не даёт наград.

## Перки китов

EpicDuels умеет только предметы, поэтому перки накладывает мост: как только
игрока телепортирует на боевую копию арены (`arena_instance_*`), он получает
эффекты своего набора. После боя эффекты снимаются (`buffs.clear-on-leave`).

| Кит | Перки по умолчанию |
|---|---|
| Классика | Скорость I |
| УХК | Скорость I, Регенерация I |
| Гаппли | Скорость I, Поглощение I |
| Сумо | Скорость II, Прыгучесть I |
| Лучник | Скорость I, Ночное зрение |
| Булава | Скорость I, Сила I + **урон от падения не проходит** |
| Топор | Скорость I, Сопротивление I |
| Тризуб | Скорость I, Подводное дыхание |
| Арбалет | Скорость I, Регенерация I |
| Незерит | Скорость I, Сопротивление I |

Свои значения — в `config.yml` (список «ЭФФЕКТ:уровень», уровень с 1):

```yaml
buffs:
  enabled: true
  duration-seconds: 900     # 15 минут, дольше любого боя
  clear-on-leave: true      # вышли с арены — эффекты сняты
  per-kit:
    булава: [SPEED:2, STRENGTH:2, RESISTANCE:2]
    сумо: [SPEED:3, JUMP_BOOST:2]
```

Имена эффектов — как в Bukkit: `SPEED`, `STRENGTH`, `RESISTANCE`,
`REGENERATION`, `JUMP_BOOST`, `ABSORPTION`, `WATER_BREATHING`,
`NIGHT_VISION`, `FIRE_RESISTANCE`, `INVISIBILITY`, `HEALTH_BOOST`.
Ключ — русское имя кита, как в `kits.names`. Эффекты выдаются только на
арене: в лобби и в `/duel` их нет.

## Скорборд в бою

Боковая панель — это `plugins/EpicDuels/scoreboard.yml`, формат форка:
`enabled`, `update-interval-ticks` и `views.<view>` (`lobby`, `duel`,
`spectator`, `queue`), в каждой — `enabled`, `title`, `lines`. Значения
подставляются в угловых скобках: `<player>`, `<opponent>`, `<kit>`,
`<arena>`, `<round>`, `<best_of>`, `<score>`, `<opponent_score>`, `<time>`.

В комплекте лежит готовый файл: в бою — время, противник, кит, карта,
раунд и счёт; у зрителя — то же без счёта раундов; в поиске и лобби
сайдбар не трогается, чтобы не перекрывать главное меню сервера.

## Арены в одном мире

Наш билд EpicDuels (`EpicDuels-ElyTriX-3.1.1.jar`) умеет держать все арены в
одном готовом мире — например, в твоём `duel`. Миры `arena_template_*`
создавать не нужно: арены отличаются только точками спавна.

```yaml
arenas:
  world: "duel"    # пусто — вернуть по миру на арену
```

```
/duelx arena create arena1
/duelx arena spawn1 arena1     # стоя в мире duel
/duelx arena spawn2 arena1
/duelx arena ready arena1
/duelx arena list | tp | remove
```

На каждый бой мир `duel` копируется в `arena_instance_*`, поэтому боёв может
идти сколько угодно одновременно, а арены друг другу не мешают: границы
считаются по точкам спавна. Для 2 на 2 отдельные точки не нужны — `spawn1` и
`spawn2` это точки команд, напарники встают рядом.

## Защита арен

На боевых копиях арен (`arena_instance_*`) мост:

- запрещает ставить блоки и выливать жидкости из ведра;
- гасит взрывы — `blockList` очищается, поэтому ни один блок арены не ломается
  (урон игрокам от взрывов остаётся);
- блокирует поджог.

Шаблоны (`arena_template_*`) не трогаются — там администратор строит арену.
Отключить можно в конфиге: `protection.block-place` и `protection.explosions`.

## Меню

Семь окон лежат в `BMenu/menu/elytrix/duel/`: главное, киты, поиск соперника,
раунды, подтверждение, статистика, помощь. Оформление повторяет дефолтное
`/menu`: имя `&7« &#F8BEFBНазвание &7»`, lore `&#F8BEFB&l┃`, закрытие
`red_dye`, кадр из чёрных и фиолетовых панелей, сборка кадра со звуками.

Главное меню: `20` — дуэль 1 на 1, `21` — бои 2 на 2, `22` — подбор
соперника, `23` — статистика, `24` — рейтинг, `31` — как играть,
`4` — профиль с победами, `45` — возврат в `/menu`, `49` — закрыть.

Групповых окон (`duel_party`, `duel_party_size`) и кнопки «Наблюдение»
больше нет, наблюдение выключено в `EpicDuels/config.yml`
(`features.spectating: false`). Бои 2 на 2 идут через пару: выбрал
тиммейта — он подтвердил — встали в очередь вдвоём.

Восьмое окно — `elytrix:duel_queue_wait`: его открывает `/duel`, пока
идёт поиск. Одна кнопка — красная «Отменить поиск»; режим, кит и время
написаны в её описании.

Окно выбора соперника (`/duelx pick`, `/duelx target`) без рамки из стёкол:
головы игроков занимают всё окно, снизу — страницы, случайный соперник,
поиск пары и закрытие.

## Статистика

Значения передаются в BMenu как `{wins}`, `{losses}`, `{winrate}`,
`{score}` — PlaceholderAPI и расширение EpicDuels не нужны.

Передаются они только тогда, когда меню открывает мост. Если открыть то
же меню кнопкой `[open]` из другого меню BMenu, цифр не будет — BMenu
не знает, чья статистика. Поэтому все кнопки статистики (в главном меню,
профиль и сама страница) вызывают `/duelx stats`, а в главном меню цифры
не выводятся вообще: там «нажми, чтобы открыть».

В `stats.yml` прописаны значения по умолчанию (`args: wins: 0` и т. д.),
поэтому вместо `{wins}` никогда не показываются фигурные скобки. Если
версия BMenu не принимает значения через API, мост пишет цифры в чат
строкой «Победы: 5 · Поражения: 2 · Побед: 71.4% · Очки: 12» и пишет
предупреждение в консоль. Включить подробный лог: `menus.debug: true`.


## API топов для сайта

Мост сам пишет `plugins/ElytrixDuelsBridge/tops.json` раз в минуту:

```json
{
  "updated": 1761000000,
  "wins": [{"place": 1, "uuid": "...", "name": "Steve", "wins": 42,
            "losses": 7, "winrate": 85.7, "score": 1180}],
  "score": [ ... то же, но по очкам ... ]
}
```

Другому плагину (или скрипту на сайте) достаточно читать файл. Если нужен
Java-вызов — класс лежит в мосте:

```java
import ru.elytrix.duelsbridge.TopsApi;

List<TopsApi.Row> top = TopsApi.topByWins(10);
for (TopsApi.Row row : top) {
    row.place(); row.name(); row.uuid();
    row.wins(); row.losses(); row.winrate(); row.score();
}
String json = TopsApi.json(10);        // тот же JSON строкой
int place = TopsApi.placeOf(uuid, "wins", 100);
```

В `plugin.yml` читающего плагина: `depend: [ElytrixDuelsBridge]`.

```yaml
api:
  tops: true
  tops-interval-seconds: 60
  tops-size: 10
  tops-file: tops.json
```

## Пара 2 на 2 и очередь

**Приглашение.** Клик по игроку в окне выбора тиммейта отправляет
приглашение; у приглашённого в чате две кнопки — `[Принять]` и
`[Отклонить]`. Приглашение живёт 60 секунд, одно на игрока. Принять можно
только когда оба свободны: не в бою, не в поиске, без пары.

**Пара.** Живёт, пока не начался бой, пока кто-то не нажмёт «Выйти из
пары» (`/duelx team leave`) или не выйдет с сервера. Кит выбирает тот,
кто позвал.

**Очередь.** Своя, родная очередь EpicDuels не используется (если игрок
всё-таки попал в неё старым меню, «Выйти» и `/duel` работают как надо —
мост видит и снимает его оттуда):

| Режим | Кто в очереди | Сколько ждёт | Как находится бой |
|---|---|---|---|
| 1 на 1 | одиночка | 180 с (`queue.timeout-seconds`) | второй игрок с тем же китом |
| 2 на 2 | пара | 300 с (`queue.team-timeout-seconds`) | вторая пара с тем же китом |
| 2 на 2 «рандом» | одиночка | 300 с | пара + двое одиночек или 4 одиночки |

Бой стартует сразу, без «нажми, чтобы присоединиться». Каждый вход в
очередь объявляется в чат с кликабельной кнопкой; у того, кто ищет, в
сообщении есть `[Выйти]`.

**Что снимает игрока с очереди:**

- истекло время поиска;
- он вышел с сервера (напарнику приходит сообщение);
- он оказался в бою (принял другой вызов, турнир) — проверка раз в секунду;
- он нажал «Отменить поиск» в окне, `[Выйти]` в чате или `/duelx queue leave`;
- напарник вышел из пары или с сервера.

Пока игрок в поиске, внизу экрана постоянно висит строка
`Поиск » Классика · 1:24` (`messages.queue-actionbar`, выключается
`queue.action-bar: false`), а `/duel` открывает окно «Ищем бой» с одной
красной кнопкой. Если поиск по каким-то причинам не идёт (например,
кончилось время), «Выйти» честно пишет «Поиск уже не идёт», а не «Ты не
в очереди».

**Киты из меню.** Игрок выбирает кит по-русски («Сумо», «УХК»), а
`KitManager` EpicDuels хранит их по id — мост переводит имя через
`Kits.canonical`/`legacyOf`, поэтому «Кит не найден: Сумо» больше не
появляется. Если кита правда нет, в сообщении перечислены существующие.

## Какие экраны заменяются

| Окно EpicDuels | Меню BMenu | Почему можно |
|---|---|---|
| `MAIN` (`/duel`) | `elytrix:duel` | статичное, 4 кнопки |
| `STATS` | `elytrix:duel_stats` | цифры передаём сами, без PAPI |
| `MATCHMAKING` | `elytrix:duel_queue` |
| `KIT_SELECT` | `elytrix:duel_kit` |
| `PARTY_KIT` | `elytrix:duel_kit` |
| `PARTY_CONFIRM` | `elytrix:duel_confirm` | состав китов у нас фиксирован |
| `ROUNDS_SELECT` | `elytrix:duel_rounds` | 1 / 3 / 5 |

Остаются за плагином (содержимое зависит от сервера):

`DUELS` (список игроков), `ARENA_SELECT`,
`KIT_LIST`, `KIT_EDITOR_LIST`, `ARENA_LIST`, `KIT_EDIT`, `KIT_PREVIEW`,
`KIT_CUSTOMIZE`.

Эти экраны перекрашены через `menus.yml` EpicDuels (названия, лор, слоты,
заголовки), но их рисует сам плагин: в статичном YAML нельзя вывести список
онлайн-игроков или арен.

## Установка

1. `EpicDuels-ElyTriX-3.1.1.jar` → `plugins/` (заменяет обычный EpicDuels 3.1.x)
2. `ElytrixDuelsBridge-1.7.1.jar` → `plugins/`
3. Папка меню BMenu `elytrix/duel/*.yml` → `plugins/BMenu/menu/elytrix/duel/`
4. Запустить сервер (или `/reload confirm` — не рекомендуется) и проверить `/duel`.
5. Если наборы уже были — `/duelx kits reset`, чтобы применить усиленный состав.
6. Топы для сайта появятся сами: `plugins/ElytrixDuelsBridge/tops.json`.

Порядок загрузки задан в `plugin.yml`: `depend: [EpicDuels, BMenu]`,
так что Bukkit сам дождётся обоих.

## Настройка

`plugins/ElytrixDuelsBridge/config.yml`:

```yaml
menus:
  MAIN: "elytrix:duel"
  STATS: "elytrix:duel_stats"
  MATCHMAKING: "elytrix:duel_queue"
  ROUNDS_SELECT: "elytrix:duel_rounds"

kits:
  auto-install: true     # создать 10 наборов, если их ещё нет

protection:
  block-place: true      # блоки и жидкости на аренах запрещены
  explosions: true       # взрывы не ломают арену

buffs:
  enabled: true          # перки китов
  duration-seconds: 900
  clear-on-leave: true

api:
  tops: true             # писать tops.json для сайта
  tops-interval-seconds: 60
  tops-size: 10
```

Поставить `keep` — окно вернётся к EpicDuels. Недостающие ключи мост
дописывает в файл при запуске сам, уже выставленные значения не трогает.
`/duelx` не требует прав.

## Сборка

Нужен JRE/JDK 17+ и компилятор ECJ. Скрипт `build.sh`:

```
bash build.sh /путь/к/jdk /путь/к/ecj.jar
```

Если в JRE нет утилиты `jar` (бывает в jlink-сборках), скрипт сам упакует
через `tools/mkjar.py`. Готовый jar кладётся в эту папку, потом копируется
в `downloads/`.

`stubs/` — минимальные заглушки Bukkit API только для компиляции; в jar они
не попадают. В архиве 36 файлов: `plugin.yml`, `config.yml` и классы моста.

Меню `elytrix/duel/*.yml` (7 штук) генерируются скриптом
`tools/gen_duel_menus.py`. Кадр, палитра, отступы и звуки повторяют
дефолтное `/menu` (`elytrix:menu`): чёрные панели сверху, фиолетовые по низу
и бокам, кнопки собираются по одной. Скрипт проверяет, что в анимации нет
ссылок на несуществующие предметы и нет двух предметов в одном слоте.

## Ограничения и риски

- Мост не тестировался на живом сервере: проверяй на копии.
- Если BMenu не найдёт меню, окно просто не откроется — в консоли будет
  ошибка BMenu; `config.yml` моста правится без пересборки.
- Отмена окна не вызывает `InventoryCloseEvent` EpicDuels, поэтому данные
  вызова (игрок/кит) живут до следующего вызова или до выхода с сервера.
- Плагин не патчит EpicDuels: при обновлении EpicDuels мост продолжит
  работать, пока не изменятся имена классов/методов `GUIManager`.
