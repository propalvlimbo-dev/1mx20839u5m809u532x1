# ElytrixCasino

Пакетное казино (рулетка) для Spigot/Paper **1.16.5+**.
NPC-крупье и колесо рулетки — пакетные сущности (VirtualEntityApi), они не грузят мир и не зависят от чанков.

## Сборка

```bash
cd ElytrixCasino
mvn clean package
```

Готовый файл: `ElytrixCasino/target/ElytrixCasino.jar` — **без версии в имени** (`<finalName>` в `pom.xml`).
Версия при этом подставляется в `plugin.yml` из `${project.version}`.

## Зависимости сервера

| Плагин | Зачем |
|---|---|
| [VirtualEntityApi](https://github.com/By1337/VirtualEntityApi) 1.4.2 | пакетные сущности |
| BLib 1.9.7 | нужен самому VirtualEntityApi (`Vec3d`, утилиты) |
| Vault + плагин экономики | ставки и выплаты |

Компилируется против `spigot-api 1.16.5` + `adventure-api` (scope `provided`):
VirtualEntityApi принимает adventure `Component`, в рантайме его отдаёт BLib/VirtualEntityApi.

## Файлы конфигурации

```
plugins/ElytrixCasino/
├── config.yml        # рулетка, автоматы, NPC, колесо, эффекты
├── messages.yml      # все сообщения
├── data.yml          # сохранённые рулетки и автоматы (координаты + ставка)
└── GUI/
    ├── roulette.yml  # меню выбора ставки
    └── automate.yml  # меню автомата
```

## Команды

| Команда | Описание |
|---|---|
| `/ec help` | помощь |
| `/ec reload` | перезагрузка конфига и повторное восстановление рулеток/автоматов |
| `/ec create roulette` | создать рулетку там, где стоишь |
| `/ec remove [id]` | удалить по id, либо режим «кликни по NPC» |
| `/ec list` | список рулеток и автоматов |
| `/ec tp <id>` | телепорт к рулетке |
| `/ec pointer pose <x> <y> <z>` | наклон указателя вживую (сохраняется в конфиг) |
| `/ec pointer offset <вбок> <высота>` | положение указателя вживую |

Права: `elytrixcasino.use` (по умолчанию всем), `elytrixcasino.admin` (op).

## Восстановление после рестарта

Рулетки и автоматы поднимаются из `data.yml` не в `onEnable`, а `CasinoLoader`'ом на первом
тике после полного старта сервера — иначе миры и чанки ещё не готовы и записи молча терялись:

* **Мир ещё не загружен** (например, его поднимает Multiverse позже нас) — запись ждёт в очереди
  и восстанавливается по `WorldLoadEvent` либо повторной попыткой раз в 5 секунд (~5 минут),
  после чего в консоль пишется, какой именно мир так и не появился. `data.yml` при этом не трогается.
* **Чанк не загружен** — автомат регистрируется сразу (`/ec list`, `/ec tp` и клик по блоку работают),
  а вывеска-голограмма поднимается вместе с чанком (`ChunkLoadEvent`) и снимается при его выгрузке,
  чтобы армор-стенды не оставались в сейве мира и не дублировались.
* Каждая запись грузится в своём `try/catch`: ошибка на одной рулетке больше не роняет загрузку остальных.
* Вывески чистятся по персональному тегу автомата, поэтому соседние автоматы, стоящие вплотную,
  больше не сносят надписи друг друга при загрузке.
* Если мир выгрузили (`/mv unload`), сущности снимаются и возвращаются в очередь — при повторной
  загрузке мира всё встанет на место.

В консоли видно, что произошло: `Загружено рулеток: 2/2, автоматов: 3/3`,
а `/ec list` дополнительно покажет автоматы с незагруженным чанком и записи, которые ещё ждут свой мир.

## Как это работает

* Крупье — пакетный **игрок** (`VirtualPlayer`) со скином: можно указать ник в `roulette.npc.skin.player`
  (текстуры подтянутся с Mojang в фоне) либо готовые `value`/`signature`. NPC прячется из таба.
* Колесо — пакетные армор-стенды, их «тикает` `PlayerTracker` в радиусе `roulette.view-radius`.
* Колесо крутится по-настоящему (ячейки едут по окружности), но угловая скорость ограничена
  `roulette.max-spin-speed`: клиент сглаживает движение сущности примерно за 3 тика и рисует хорду
  вместо дуги, поэтому на большой скорости колесо визуально «стягивается» к центру.
  Лишние обороты автоматически урезаются, а остаточное сжатие компенсируется небольшим
  увеличением радиуса (`wheel.radius-compensation`).
* Профиль вращения: разгон → ровное вращение → мягкое торможение, с точной остановкой сектора под указателем.
* Пакетные сущности **не генерируют событий клика**: клиент шлёт серверу `interact entity`
  с неизвестным id, и Bukkit не выдаёт ни `PlayerInteractEvent`, ни `PlayerInteractEntityEvent`.
  Поэтому плагин сам слушает входящие пакеты через netty-пайплайн игрока
  (`VirtualInteractionInjector`, всё на рефлексии, без NMS-импортов и без ProtocolLib).
  Рейтрейс по `PlayerInteractEvent`/`PlayerAnimationEvent` оставлен запасным путём.
* NPC поворачивается к ближайшему игроку в радиусе `roulette.look-radius`, во время раскрутки смотрит на колесо,
  а после второго удара переводит взгляд на указатель. Все повороты идут через интерполяцию
  (`look-turn-speed` / `walk-turn-speed`), поэтому голова не дёргается.
* Если монет не хватает — NPC отрицательно качает головой.
* Победный сектор выбирается по весам **до** анимации, колесо докручивается ровно
  до указателя, выплата берётся из того же сектора — рассинхрона «показал одно, выплатил другое» нет.
