# ElytrixTrader

Уникальные торговцы для **Minecraft 1.16.5+** (Spigot/Paper, Java 17). Торговец может появляться в случайном
месте или в настроенной фиксированной точке, выглядеть как игрок со скином из конфига, показывать голограмму
и открывать меню сделок по ПКМ. На современных серверах голограмма использует TextDisplay с прозрачным фоном;
на старых версиях остаётся виртуальная стойка как совместимый fallback.

В комплекте **Опытный Торговец** (случайное место в обычном мире) и **Призрачный торговец** (остров дракона
в Эндер-мире; расчёты настраиваются Призрачными осколками). Предложения и цены для него намеренно не заданы;
владелец сервера может добавить их через `/etr edit ghost`.

## Зависимости (сервер)

| Плагин | Версия | Тип |
| --- | --- | --- |
| VirtualEntityApi | 1.4.2 | обязательно (`depend`) |
| BLib | 1.9.7 | обязательно (`depend`) |
| FastAsyncWorldEdit | 2.4.10 (или WorldEdit 7.2.x) | для схем, `softdepend` |
| Vault + любой эконом-плагин | 1.7 | для оплаты монетами, `softdepend` |
| PlaceholderAPI | 2.11.6 | для плейсхолдеров, `softdepend` |

Сборка: `mvn clean package` → `target/ElytrixTrader.jar` (имя без версии). Все зависимости `provided`,
внутрь джара не кладутся.

## Установка

1. `ElytrixTrader.jar` в `plugins/`.
2. Положить схемы в `plugins/ElytrixTrader/schematics/` (`.schem`, `.schematic` — то, что читает FAWE/WorldEdit).
3. Для призрачного торговца конфиг указывает **именно `ghost.schem`**. Оригинальный файл в исходном комплекте
   отсутствует и не заменяется другой схемой: положите оригинал в `plugins/ElytrixTrader/schematics/ghost.schem`
   (или в каталог схем WorldEdit/FAWE), иначе торговец появится без постройки.
4. Имена остальных файлов схем указываются в файлах торговцев (`schematic.file`), иначе торговец заспавнится
   без соответствующей постройки.
5. В схеме блоком **улья (BEEHIVE)** разметить середину постройки — торговец встанет ровно на него
   (материал маркера меняется в `schematic.marker-material`).
6. Перезапустить сервер.

### Валюта Ghost Trader

Для сделок Ghost Trader допустим ровно один тип цены — канонический Призрачный осколок Cemetery с PDC
`elytrixcemetery:item_id=ghost_shard` (поддерживается и известный legacy PDC `elytrixdungeons:item_id`).
В `/etr edit ghost` возьмите нужный стек настоящих осколков в основную руку и нажмите ЛКМ по кнопке цены;
ПКМ очищает цену. Опыт, обычные предметы и смешанные цены отклоняются и не списываются. Товары и их цены
не заданы заранее; пока для сделки не указан кастомный осколок, купить её нельзя.

## Структура конфигов

| Файл | Назначение |
| --- | --- |
| `config.yml` | глобальные настройки спавна, взаимодействия, голограмм, скинов, схем, broadcast'ов, валют |
| `traders/*.yml` | сами торговцы — по файлу на вид: имя, скин, миры, место спавна, схема, голограмма |
| `trader_trades/*.yml` | сделки торговцев (создаются/правятся в игре через `/etr edit`, заменяют `trades.yml`) |
| `gui.yml` | анимированное меню ElytriX: размер, слоты сделок, панели, автокнопки, лор и темп анимации |
| `messages.yml` | все сообщения игроку и `broadcast`-строки |
| `cooldowns.yml` | кулдауны игроков (создаётся автоматически) |

### `config.yml`

* `settings.trade-cooldown-seconds` — перерыв между покупками у торговцев этого типа (0 = выключен).
* `spawn.interval-seconds`, `spawn.chance` — каждые N секунд с вероятностью `chance` плагин пытается заспавнить
  торговца; `spawn.max-per-trader` и `spawn.max-total` ограничивают количество.
* `spawn.min-radius` / `max-radius` — кольцо поиска вокруг спавна мира (или `location.center` торговца);
  `lifetime-seconds` — время жизни, после чего торговец исчезает.
* `interaction.radius` — дистанция для открытия меню; `interaction.view-distance` — радиус chunks-трекера
  виртуальных сущностей (в чанках, 16 блоков за единицу).
* `currency.coins-placeholder` — откуда брать баланс монет (любой PlaceholderAPI-плейсхолдер, например
  `%playerpoints_points%`, `%coinsengine%`).
* `currency.coins-spend-command` — команда списания монет с `{player}` и `{amount}`.
* `broadcast.spawn/despawn/purchase` — какие сообщения уходят в чат, `purchase.threshold` — с какого количества
  предметов начинать спамить в эфир.

### `traders/` — файл на каждый вид торговца

Каждый торговец — отдельный файл `plugins/ElytrixTrader/traders/<id>.yml` (id = имя файла):

```yaml
# traders/experienced.yml
display-name: '&#F8BEFB&lОпытный Торговец'
skin: 'Steve'
worlds: ['world']
random-trades: 12            # сколько случайных предметов показывать в меню
trade-cooldown-seconds: 60   # перерыв между покупками, секунд
location:
  center: world-spawn        # или 'x;z'
  min-radius: 450
  max-radius: 1400
  min-height: 0
  max-height: 0
  min-distance-from-player: 32
  require-floor: true
schematic:
  file: 'experienced_trader'
  marker-material: BEEHIVE   # блок-маркер центра схемы: на нём стоит торговец
  rotation: 0                # 0/90/180/270
  offset-x: 0
  offset-y: 1
  offset-z: 0
  clear-radius: 0            # 0 — ничего не зачищать перед вставкой
hologram:
  height: 2.35               # от земли до первой строки
  line-height: 0.28          # шаг между строками
  lines: [...]
```

Для фиксированного спавна можно задать `spawn.world/x/y/z`; `search-radius` ограничивает поиск
подходящего безопасного места вокруг точки:

```yaml
spawn:
  world: 'world_the_end'
  x: 5.5
  y: 65.0
  z: 0.5
  search-radius: 8
```

`hologram.lines` — плейсхолдеры `{trader}`, `{left}`, `{seconds}`, `{world}`, `{x}`, `{y}`, `{z}`, `{count}`,
`{max}`, `{uid}` + любые плейсхолдеры PlaceholderAPI. Строки вида `#ICON: material` не удалять — они используются
для вспомогательных элементов.

### PlaceholderAPI

Глобальные плейсхолдеры `%elytrixtrader_status%`, `%elytrixtrader_time%`, `%elytrixtrader_location%`,
`%elytrixtrader_world%`, `%elytrixtrader_x%`, `%elytrixtrader_y%`, `%elytrixtrader_z%` сохранены для совместимости.
Для конкретного торговца используйте формат `%elytrixtrader_<id>_<field>%`, например
`%elytrixtrader_experienced_x%` и `%elytrixtrader_ghost_location%`. Поддерживаются `status`, `time`, `location`,
`location_full`, `world`, `x`, `y`, `z`, `count` и `name`. Для фиксированного спавна координаты и мир доступны
даже до появления NPC; для случайного — фактические координаты доступны во время события. Пока торговец неактивен,
`time` показывает ближайшее общее время расписания, а не отдельный таймер конкретного типа торговца.

### `trades.yml`

```yaml
diamond_block:
  display-name: '&#F8BEFB&lАлмазный блок'
  max-per-trade: 8            # за одну сделку
  stock: 3                    # всего на одного торговца, -1 = безлимит
  cost:
    - type: experience_levels # experience_levels | experience_points | vault | coins | item | placeholder
      amount: 15
    - type: item
      material: diamond
      amount: 4
  receive:
    - material: diamond_block
      amount: 1
  commands: []                # выполняются от консоли после покупки, {player}, {amount}
  required-level: 0
  permission: ''
  worlds: []
```

`icon` — чем торговец показывает товар в меню, `lore` — дополнительный текст (переопределяется `gui.yml`,
если `icons.trade.override-trade-lore: true`).

`{trade}`, `{price}`, `{currency}`, `{balance}`, `{stock}`, `{trader}`,
`{left}`, `{world}`, `{x}`, `{y}`, `{z}`, `{page}`, `{pages}`, `{player}`, `{levels}`, `{exp}`.

## Как это работает

* Торговец — `VirtualPlayer` из VirtualEntityApi: id выделяются из диапазона `2^30`, поэтому не пересекаются
  с реальными сущностями; имя и скин (`setTexture(value, signature)`) ставятся до первого тика, затем `respawn()`.
  Весь код работы с VirtualEntity собран в одном классе `virtual/TraderNpc.java` (NPC + голограмма + общий
  `PlayerTracker` видимости) — `TraderInstance` только координирует.
* Голограмма — один `TextDisplay` над торговцем с отключённым стандартным фоном и прозрачным background-color;
  строки перерисовываются только при изменении текста. На версиях без `TextDisplay` используется совместимый
  fallback из виртуальных `VirtualArmorStand`.
* Клик — netty-хук в пайплайн игрока: пакет использования сущности перехватывается до декодера, id сопоставляется
  с активным торговцем, меню открывается в основном потоке. Если рефлексия недоступна, работает запасной вариант через
  `PlayerInteractEvent` (ПКМ рядом с торговцем).
* Сделки проверяются полностью до списания: сначала все проверки, потом оплата, потом выдача. Инвентарь переполнен
  — лишнее падает под ноги.
* Скины тянутся асинхронно (Mojang session API, кэш на `skins.cache-seconds`); если ник игрока не найден,
  торговец остаётся со стандартным скином.
### Аура торговца и анимация покупки — частицы

Вокруг каждого торговца вьётся тихая аура — зелёные частицы по наклонным
орбитам. Частицы при покупке убраны: при сделке остаётся только звук
и короткий взмах руки торговца.

**VirtualExperienceOrb больше не используется вообще.** Опыт показал: в 1.16.5
клиент САМ тикает сущности XP-орбов (`ExperienceOrbEntity.tick` выполняется на
клиенте): магнит тянет орб к любому игроку ближе 8 блоков, плюс гравитация,
затухание ×0.98 и самоуничтожение по возрасту 6000 тиков. Серверными флагами
это не отключается (NoGravity отключает только гравитацию, магнит — никогда).
Что бы сервер ни отправлял (позиция каждый тик, обнуление скорости,
компенсация магнита — всё это пробовалось в предыдущих версиях), рядом с
игроком орб неизбежно «дрожал» и улетал к нему — это ванильное поведение
клиента, его невозможно починить на стороне сервера.

Поэтому обе анимации переведены на **частицы** (`virtual/AuraEffect.java` и
`animation/PurchaseAnimation.java`):

* у частиц нет клиентской физики, интерполяции и магнита — дёргаться нечему
  в принципе, при любом TPS и любом количестве игроков рядом;
* визуал — ТИХИЙ зелёный вихрь: 7 точек на индивидуальных орбитам радиусом
  ~1.3 бл (наклонные плоскости, мягкий пульс, вертикальная волна). Частица —
  только мелкая зелёная «пыль» Particle.REDSTONE (DustOptions: цвет #8CE99A,
  размер 0.65 — меньше стандартного), спавн раз в 3 тика, по одной точке:
  видно именно вращение, без шлейфов. Изумрудные искры (VILLAGER_HAPPY),
  END_ROD и PORTAL из ауры убраны — летает одна тихая зелёная «дымка»;
* зелёная пыль та же используется в анимации исчезновения (спираль вокруг
  поднимающегося NPC, крошка блоков, финальный салют) — единый стиль;
* пакеты отправляются только игрокам в радиусе 40 блоков от торговца
  (`Player#spawnParticle`), дальним игрокам — ноль трафика;
* анимация покупки — «сферы» летят от груди игрока к груди торговца по
  кривым Безье (smoothstep: мягкий разгон и торможение), старт следует за
  игроком, если он отошёл; у груди торговца — вспышка, звук подбора опыта
  и взмах рукой;
* ауру можно выключить в `config.yml` → `aura.enabled: false`.

### Лут и меню торговца

* Меню оформлено в фирменных чёрно-пурпурных цветах ElytriX: рамка и товары
  появляются каскадом, анимация настраивается в `gui.yml` → `animation`.
  Слоты товаров задаются в `trade-area.slots`; нижняя панель автоматически
  содержит информацию о торговце, закрытие и навигацию по страницам.
* Если предложений нет, показывается аккуратная заглушка; Ghost Trader сообщает,
  что предложения и цены ещё не настроены.
* **Лут случайный.** При спавне каждый торговец берёт из пула `/etr edit`
  случайные предметы — `random-trades` в файле торговца (сколько взять).
  Меню показывает именно эту выборку; два торговца одного вида предлагают
  разные наборы. Сток у каждой позиции свой и не бесконечен (0 = «РАСКУПИЛИ»).

### Редактор /etr edit

* **Слот 49 — инфо-книга** (в стиле сообщений): «это весь пул предметов,
  торговец берёт из него случайные позиции при каждом спавне, лут
  не бесконечный — раскупается» + подсказки кликов (ЛКМ — редактировать,
  Shift+ЛКМ — дублировать, ПКМ — удалить, Shift+ЛКМ по предмету в своём
  инвентаре — добавить в пул).
* Кнопка «Закрыть» переехала из слота 49 в **слот 48**.
* Список трейдов пагинируется: 45 предметов на страницу (слоты 0-44);
  когда все заняты — в **слоте 53** появляется стрелка «Вперёд» (страница 2),
  на второй и дальше в **слоте 45** — «Назад».

### Где стоит торговец — блок-маркер схематики

Автор схематики размечает середину постройки специальным блоком — по умолчанию
**ульем (BEEHIVE)**. После вставки схемы плагин ищет этот блок (сначала среди
поставленных схемой блоков, затем по всему объёму вставки с учётом поворота)
и ставит торговца ровно на него: ноги — на верхней грани блока, по центру.
Над маркером нужно оставить 2 блока воздуха под рост NPC.

Материал маркера настраивается в файле торговца:

```yaml
schematic:
  file: 'experienced_trader'
  marker-material: BEEHIVE   # блок-маркер центра, на нём стоит торговец
```

BEEHIVE выбран потому, что он не генерируется в природе (в отличие от
BEE_NEST) — плагин никогда не спутает маркер с естественным блоком. Если
маркер в схеме не найден, работает запасная логика: NPC ставится на 1 блок
выше самой высокой точки поставленных блоков схемы.

### Исчезновение ивента — «вознесение» торговца

Когда истекает время жизни торговца (или `/etr stop` / `/etr kill` с
анимацией), запускается `animation/DisappearAnimation.java` (~7 с,
сдержанно, без взрывов и салютов):

1. Блоки схематики мягко растворяются СНИЗУ ВВЕРХ: каждый блок в свой
   момент (высота + лёгкий случайный разброс, граница «дышит») уходит
   в пару тихих крошек своей текстуры и редкую пылинку.
2. Торговец плавно поднимается на ~3.5 бл и медленно поворачивается
   (~1.5 оборота); движение — smootherstep: без рывка на старте и без
   резкой остановки в конце.
3. Под ним тянется тонкий столб зелёной пыли («дорожка света»), вокруг
   медленно идут две точки по спирали.
4. Финал: немного чар, пара искр и мягкое расходящееся кольцо зелёной
   пыли; негромкие звуки маяка и телепорта — торговец исчезает, террейн
   под постройкой восстанавливается.
